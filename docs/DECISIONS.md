# Decisions

One line per decision taken while building (roadmap §0 rule 9). Newest at the bottom of each milestone.

## M1 — Core loop

- **2026-10-08 · Files in R2, not KV.** The provided Cloudflare token has no KV permission, but R2 is enabled on the account and the token can use it. Bucket `fichas-files`, binding `FILES`. Same free tier, made for files; no token change needed from the owner.
- **2026-10-08 · Vitest 5 + `@cloudflare/vitest-plugin` 1.4.0.** `@cloudflare/vitest-pool-workers` was renamed and its last version needs Vitest 4; the renamed plugin supports Vitest 5 and matches wrangler 4.149.0.
- **2026-10-08 · npm 11 for installs.** npm 10.9 crashes (`edgesOut` of null) resolving Vitest's optional browser peers; `npx npm@11 install` works. Lockfile is standard.
- **2026-10-08 · No `@preact/preset-vite`.** Vite 8 compiles JSX with Oxc (`oxc.jsx.importSource: 'preact'`); no Babel, fewer moving parts. No HMR prefresh in dev (full reload is fine).
- **2026-10-08 · No `vite-plugin-pwa`.** A 60-line build plugin (`scripts/vite-sw.ts`) builds `src/client/sw.ts` as an extra entry and injects the precache list into `self.__WB_MANIFEST`. No Workbox runtime (≈ 10 KB saved), no extra dependency tree.
- **2026-10-08 · TypeScript 7.0.2 (native) for type checking only.** Vite transpiles; four tsconfigs (app/sw/worker/node) because DOM, WebWorker and Workers types conflict.
- **2026-10-08 · Shell precached as `/`, not `/index.html`.** Workers Static Assets redirect `/index.html` → `/`, and a service worker cannot answer a navigation with a redirected response.
- **2026-10-08 · Pull sends JSON columns as strings.** The Worker never parses/re-encodes row JSON (CPU budget); the client parses per column.
- **2026-10-08 · Outbox stores references, not rows.** Flush reads the latest row version; deletes are soft-delete upserts, so `op: 'delete'` is unused by the client. A row the server rejects (400) is isolated and dropped so it can't block the queue; the error is reported to `client_errors`.
- **2026-10-08 · Recipe upsert ends with `ON CONFLICT DO NOTHING`.** A second device creating the same fingerprint offline can't fail the whole sync batch.
- **2026-10-08 · Rate limits reuse `auth_attempts` with key prefixes** (`pair:<ip>`, later `ai:<session>`). Pairing counts failed attempts only (5/hour/IP); successful pairings aren't the brute-force risk.
- **2026-10-08 · Extra endpoints:** `GET /api/auth/sessions`, `POST /api/auth/sessions/:id/revoke` (Ajustes → Dispositivos) and `GET /api/diagnostics` (p50/p90 of UX events).
- **2026-10-08 · `Secure` cookie flag only over HTTPS.** Production is always HTTPS; local dev/E2E run on http://localhost.
- **2026-10-08 · Pairing code is accent/case/space-insensitive** (iPhone keyboards capitalize and add accents). Still compared in constant time.
- **2026-10-08 · Composer: first tap on a food fills that type's missing units, then +1 per tap; tabs auto-advance.** One unit per tap made a full Comida 12+ taps; this keeps A20 at ≤ 8.
- **2026-10-08 · "Que cuadre" is offered only when ≤ 3 changes reach `on`.** Otherwise fitting rewrites the meal (e.g., a dinner described under a fruit snack).
- **2026-10-08 · Learned slot times use only logs within ±3 h of the plan time, excluding backfills,** so late "pendiente" taps don't drag the window.
- **2026-10-08 · Local matcher: missing amounts assume the slot's remaining units (≥ 1), marked "supuse".** Cooking descriptors (revuelto, natural, entero…) are skipped; limón/salsa/chile count as free.
- **2026-10-08 · Calorie notes are stored but never shown** (e.g., "barra de cereal: menos de 90 kcal", R13). The plan view shows the food and portion only.
- **2026-10-08 · Seed adds "verdura cruda" (2 tz).** The PDF's line reads "2 tza verdura cruda, espinaca, …"; Appendix A listed only the named vegetables.
- **2026-10-08 · Seed dishes keep the nutritionist's option order** (first option suggested first) via `created_at` tie-break.
- **2026-10-08 · The meal card stays on the just-logged meal for 1.1 s** (tokens pop, ✓), then moves to the next slot.
- **2026-10-08 · Toast moves to the top while a sheet is open** so "Deshacer" never covers sheet buttons.
- **2026-10-08 · Plan files live in R2 as base64 text** (as uploaded), including the seeded PDF. The Worker never decodes them; the client decodes for download (M3).
- **2026-10-08 · Button word limit ignores symbols** (✓, ↻, ✎ are the "optional icon"). "Con lo que tengo" → "Lo que tengo" (≤ 3 words); "Ármalo" rephrased because it contains the banned substring "malo".
- **2026-10-08 · Copy pools `log.undo`, `log.removed`, `log.newDish`, `push.body.plan` extended to 5 variants** to meet the pool rule (Appendix C had 1–3).
- **2026-10-08 · Resumed M1 before starting M2.** Cloudflare had resources but no Worker deployment or remote migration; completed the production bootstrap and recorded actual milestone gaps in `docs/PROGRESS.md`.
- **2026-10-08 · Lighthouse CI uses Puppeteer Core with the existing Playwright Chromium** instead of downloading another browser; audit the authenticated returning-user screen with IndexedDB and the app shell retained. Reports stay local because they can include plan data. [Official Lighthouse CI configuration](https://googlechrome.github.io/lighthouse-ci/docs/configuration.html).
- **2026-10-08 · Production smoke checks do not mutate food data.** Full offline-write/reconnect coverage runs against local D1; the production browser smoke reads the plan and verifies offline rendering, then revokes its session. Automatic approval review rejected the proposed temporary production meal test.
- **2026-10-08 · Accessible pending buttons include their visible text.** Lighthouse's label-content-name audit is enforced explicitly, even though that audit does not reduce the accessibility category score.
- **2026-10-08 · M1 physical acceptance remains separate from automated results.** Owner confirmed iPhone/iOS 16.4+; do not mark physical checks complete or start M2 until those checks pass.
- **2026-10-08 · Logging supports food from any source, independently of pantry.** Owner explicitly confirmed street food and home cooking. Pantry limits Kitchen suggestions only; enforce empty/out-of-stock pantry cases when implementing M2.

Original downloads return authenticated base64 text for browser decoding, matching the existing R2 decision.

Review requires a choice for every disagreement; a single successful reader and consistency warnings require explicit acknowledgement. Targets remain editable by half-unit steppers; no silent correction of unusual printed portions.

Repeated confirmation returns the original result. Database triggers enforce immutable confirmed plan data/start/season and immutable log plan/day/slot/target snapshots. [D1 atomic batches](https://developers.cloudflare.com/d1/worker-api/d1-database/).

## Fichas 1.0 redesign (2026-10-09)

The owner asked for a complete redesign (audit → design system → build) and later for autonomous completion with gradual deployments. Audit and spec: [03-redesign.md](03-redesign.md).

- **IA: Hoy · Cocina · (+) · Jardín · Progreso.** Story split in two: the garden (game) and progress (weight, season numbers, report, plan, settings). The central "+" opens "¿Qué comiste?" for the shown day and meal. Old `/historia…` URLs and push links are canonicalized to `/progreso…`; the renewal push now points to `/progreso/plan/nuevo`.
- **One day model.** A Monday-first week strip (plants as day markers), ‹ › and a native date picker select any day since the first plan; tomorrow is a planning view. Logs for another day get source `backfill` and the slot's planned local time (`zonedTime`), so learned meal times stay clean. The day resets to today after 30 min in the background.
- **Hero first.** The current meal card renders right after the strip; optional banners and "Tu día" follow. The primary action stays above the tab bar on a 390×844 screen even with a banner (the first build put it below the fold; caught in visual QA).
- **Cuadrar el día on by default (owner request; overrides roadmap §3.5).** Effective rule: explicit owner setting, else an explicit plan rule, else allowed. Only overages of carbohydrates, sugars, fats, fruit and dairy are balanced; protein, legumes and vegetables are never reduced; a meal keeps ≥ ½ of each target; whole units first; largest remaining target first, ties to the later meal; unders never carry forward; nothing crosses days. Log target snapshots stay immutable (DB trigger). Copy says "cuadrar", never "compensar" (lint). `effectiveTargets` replaced by `balanceDay`.
- **"Tu día" gauges** show eaten ÷ the day's planned total per type, normalized per slot with the plan's swap rules; extras decompose fully.
- **Coins.** Fichas are grouped per type in tinted capsules; empty = inset socket, full = raised coin, extra = coin with a scaled "+" badge. The hero picks 30/27/24/22 px by coin count so a full meal fits one row.
- **Garden species.** 23 species (18 regular in tiers at levels 1, 2, 4, 6, 8, 10; 3 rare at ~12 %; cempasúchil and nochebuena own their calendar windows), deterministic by day and by the level at the day's start. The species stays secret until bloom. Stages: seed → sprout (1) → bud (2) → bloom (3, or 2 once the day is closed/past) → full (casa llena) → gold (día redondo). Discoveries persist as `unlock:species_<id>` achievements so the herbarium never shrinks. A unit test forbids red petals (anti-shame rule 1). Petal-style unlocks are retired; the `style.petal` setting is ignored.
- **Visitors are derived, not stored:** bees on full days, a butterfly on gold days, monarchs over the current week when it has ≥ 5 days with ≥ 2 meals.
- **New stamp "Día cuadrado":** every planned meal logged, at least one over, and the day still ends within plan totals — rewards flexible control (Westenhoefer 1999) without praising eating less.
- **Weight trend: local linear smoothing (±14 days, tricube).** An exponential average lags while losing weight and showed a trend above recent weigh-ins (caught in visual QA); local linear regression has no lag on straight declines and still cuts noise. Rate: 28-day least squares with an 80 % Student-t interval (≥ 4 weigh-ins over ≥ 10 days). Signal: losing / steady / gaining / unclear / few / none; "fast" at > 1 %/week suggests talking to the nutritionist. Projection: 4 weeks with a widening band. Neutral colors, no goal line; weight still never appears on Hoy, in toasts or in push.
- **Weight chart (dataviz checks).** Trend in `--accent-ink`, weigh-ins in `--ink-3`, nutritionist weigh-ins as diamonds. Validator: light passes CVD separation (ΔE 10.9); dark is in the 6–8 band (ΔE 7.0), legal with the secondary encodings used (line vs dots vs diamonds, legend). The gray deliberately fails the chroma floor (de-emphasis). Crosshair + tooltip on pointer and arrow keys; the history list is the table view.
- **Kitchen: Despensa · Platos · Lista.** Ideas first with a meal picker; pantry as rows grouped by food type (one tap toggles have/out; the name opens a food sheet with what it counts as, manual linking to any plan food, AI retry, "siempre tengo" and removal). "Tus platos" (favorites boost suggestions) moved here from Story. The list has an empty state and native share.
- **Rewards.** Synthesized marimba (sine body + 3.93× partial + bandpassed click + small echo) replaces sine beeps; daily bloom reveal and first-discovery cards with a one-line fact; confetti or papel picado (canvas, no library) for levels, surprises and rare finds; day close is a bloom moment. Reduced motion → fades only.
- **Interaction details.** Focus rings only after keyboard use (`data-kbd`); sheets keep mounted 210 ms to slide out and dismiss on fast drags; hold-to-repeat weight steppers start after 420 ms and never double-count the release click.
- **Startup budget (initial JS ≤ 90 KB gzip).** The first build was 95.6 KB. Rewards evaluation (`game-eval.ts`), the detailed plant renderer (`Plant.tsx`, with a tiny `MiniPlant` placeholder), confetti and tomorrow's menu load lazily; screen-only copy lives in `copy/more.ts` and push copy in `copy/push.ts` (Worker). Result: 88.2 KB.
- **Copy.** "tu nutri" everywhere (the plan used both genders). Tailwind's `overline` utility collided with the label class; renamed `.kicker`. Today stays ≤ 20 words: compact suggestion tags and the evening "Cerrar el día" button from 21:00 (it is also always in the "Tu día" sheet).
- **Visual QA tool.** `scripts/screens.ts` seeds a disposable local preview with a realistic fortnight and captures every screen (iPhone 13, light/dark) into ignored `private/tmp/screens/`. It refuses non-local URLs.
- **"Novedades" only for upgrades.** The one-time "Fichas, renovada" sheet shows only in an installed app whose Today snapshot was written by 0.8 (`v: 2`). A newly paired device has nothing to compare with, and the sheet was covering first-run cards in standalone tests.
- **Repeated slot names get their time.** The plan reader strips "Colación 1/2" to "Colación". Wherever names appear without a time (Cocina's meal picker, tomorrow's menu, the Describe meal picker), a repeated name shows its learned time ("Colación · 1 pm"). The meal card and timeline already show times.
- **Deterministic test hooks.** Today's banner slot exposes `data-ready` once rewards are evaluated, and `<html data-warm>` marks that the first-paint sheets have loaded. Tests wait on these instead of racing the startup layout or going offline mid-download (the installed app precaches those chunks).
- **Accessible names come from content.** Lighthouse flagged week-strip buttons named "lunes 5: 0 comidas" while showing "L 5" (WCAG 2.5.3). Day cells, pantry rows, tomorrow's menu rows, the stamps tile and season start now take their name from their visible text, plus hidden context where needed ("lunes 5, 2 comidas, Botón").
- **`--ink-3` is not a text color.** At 3.6:1 it only passes for icons and chart marks, and placeholders keep it. Every small text that used it (meal times, tab labels, weekday initials, garden numbers, chart axes, the herbarium's "Por descubrir", out-of-stock pantry names) moved to `--ink-2`.
- **Relinking a pantry food.** A linked food can now change what it counts as ("Cambiar" in its sheet), so a wrong AI match no longer means deleting and re-adding the food.
- **Balancing toasts tell the truth.** "Lo cuadramos" lines (`log.overBalanced`) appear only when cuadrar el día actually trims that type in a later meal. Off, for protein/vegetables, or with nothing left to absorb, the neutral `log.overSmall` lines are used instead.
- **No scores in copy.** The weekly recap counts days logged ("5 días anotados"), never "5 de 7". "Mañana, borrón y cuenta nueva" implied that the day needed erasing, so it was replaced by "Lo anotado ya está en tu jardín". Level copy avoids number agreement ("Desbloqueas tres flores nuevas") and has a singular form ("Falta 1 comida").

## Fichas 1.2 — "¿Cómo voy?" (2026-10-21)

The owner asked to simplify Hoy around two moments (decide before a meal, record after it), to show how the day is going graphically, to integrate JEV for live feedback, and to remove first-person copy. Audit and spec: [04-today-2.md](04-today-2.md).

- **Fit never adds foods to a suggestion.** The owner's "Leche + piña + chocolate" came from `fit()` padding the dish "Leche" up to the snack's target. Suggestions may change portions or drop a food; candidates that need additions are dropped (accepted menus excepted, kept as written). The fallback that returned non-fitting candidates is removed; `fromTarget` still guarantees one idea.
- **`dayStatus` is the single source for "¿cómo voy?".** Meters, pace (net of resolved meals) and advice are derived from `balanceDay`; Today, Describe's preview and the day sheet call the same function. The snapshot moves to `v: 4`.
- **The number on a tank is what's left of the whole day**, not of the next meal: the owner's decision ("¿otra tortilla?") is about the day. The pace notch marks the plan for resolved meals; unders still never carry into later targets (03 §3.3 unchanged).
- **Phase by the clock.** Before a slot's learned time the now card helps decide; from that time it asks what was eaten. `currentSlot` still chooses which slot.
- **"Me late" writes an accepted menu row** (same table as tomorrow's menu), so "Me lo comí" only ever logs a dish the owner chose; it is undoable and syncs like any menu.
- **JEV via the official System One API.** Endpoint `POST /v1/systemone`, model `jev-latest`, typed `noul` questions (shape taken from the official `typesafe-sdk` 0.7.5 OpenAPI models; docs hosts were unreachable from the build sandbox). One request per unknown phrase (≤ 6 in parallel, Workers' connection limit), 4 s timeout, no retries, cached by normalized phrase. Groups only — portions stay with the plan table / meal AI, which already passes the parse eval. Not counted against the OpenRouter daily cap (different provider, ~US$0.0004 per phrase); limited to 300 phrases/hour per session.
- **Meal AI runs on a 900 ms pause** instead of a "Ver porciones" tap, only when unknown phrases remain. Server cache and the 60/h limit are unchanged; "Anotar" before it answers waits for the same request.
- **Enter hides the keyboard, never logs.** Live preview made the old Enter-to-preview redundant, and a "Listo" tap must not record a meal.
- **No "Que cuadre" when logging.** Adjusting portions of something already eaten would falsify the record; the fit lives only in check mode ("Ajustar"), with the change spelled out first.
- **Photo from the meal sheet now reaches Describe** (`photo` and `mode` are passed through `renderSheet`); offline descriptions keep their day (`logPendingDescription(text, slot, day)`).
- **Copy lint bans first-person app phrases.** Owner-voice buttons stay. Unused strings from the old flow were deleted.
- **Today word budget 20 → 25** (browser test), because the pace line is words by design.
- **Initial JS stays within budget:** 89.3 KB of 90 KB gzip (DayMeter and NowCard are on the first paint; Describe stays lazy).
